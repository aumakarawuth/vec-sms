# แอปนักศึกษาและผู้ปกครอง

Flutter ต่อกับ [`../api`](../api) ครอบคลุมหน้าจอ A-01 ถึง A-04 ตามที่ออกแบบไว้

**สถานะ** — `dart analyze` ไม่มีข้อทักท้วง และเทสต์ผ่านครบ 40 ข้อ บน Flutter 3.44.9 / Dart 3.12.2

โฟลเดอร์นี้มี **สองแอปที่ build แยกกัน** จากโค้ดชุดเดียว

| entrypoint | ใครใช้ | build ไปไว้ที่ไหน |
|---|---|---|
| `lib/main.dart` | นักศึกษาและผู้ปกครองของวิทยาลัย | เว็บ/แอปของแต่ละวิทยาลัย |
| `lib/main_platform.dart` | ผู้ให้บริการระบบ (ข้ามวิทยาลัย) | โดเมนของผู้ให้บริการเท่านั้น |

**ห้ามรวมเป็นบันเดิลเดียวกัน** — ถ้าหน้าจอผู้ให้บริการอยู่ในแอปที่ส่งให้
ลูกค้า ทุกเครื่องที่ติดตั้งจะมีหน้าล็อกอินของระบบหลังบ้านติดไปด้วย

---

## เริ่มใช้งาน

```bash
cd app
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000/api/v1
```

`10.0.2.2` คือ localhost ของเครื่องโฮสต์เมื่อมองจาก Android Emulator
บนเครื่องจริงให้ใส่ IP ของเซิร์ฟเวอร์แทน

```bash
flutter test        # เทสต์ทั้งหมด
dart analyze .      # ตรวจโค้ด (ใช้ dart ไม่ใช่ flutter analyze)
```

### build เป็นเว็บ

```bash
flutter build web --release \
  --dart-define=API_BASE_URL=https://<โดเมน API>/api/v1 \
  --dart-define=INSTITUTION_ID=<uuid ของวิทยาลัย> \
  --dart-define=TERM_ID=<uuid ของภาคเรียนปัจจุบัน>
```

ได้ static site ใน `build/web` วางที่ไหนก็ได้ — Cloudflare Pages, Netlify,
Vercel, Firebase Hosting หรือ nginx

**ต้องตั้ง `CORS_ORIGINS` ฝั่ง API ให้ตรงกับโดเมนที่วางไว้** มิฉะนั้นเบราว์เซอร์
จะบล็อกทุกคำขอ และหน้าจอจะว่างโดยไม่มีข้อความผิดพลาดที่ชัดเจน — ดู
[`../DEPLOY-ONLINE.md`](../DEPLOY-ONLINE.md)

### build หน้าจอผู้ให้บริการ

```bash
flutter build web --release -t lib/main_platform.dart \
  --output build/platform \
  --dart-define=API_BASE_URL=https://<โดเมน API>/api/v1

# ทั้งสอง entrypoint ใช้ web/index.html ร่วมกัน (Flutter ไม่รองรับแยกราย target)
# ชื่อหน้าจะถูกตั้งใหม่ตอนแอปบูตอยู่แล้ว บรรทัดนี้แค่กันไม่ให้ชื่อของ
# แอปนักศึกษาโผล่ในแท็บช่วงเสี้ยววินาทีก่อนบูต และในประวัติเบราว์เซอร์
sed -i 's|<title>.*</title>|<title>ผู้ดูแลข้ามวิทยาลัย</title>|' build/platform/index.html
```

ไม่ต้องส่ง `INSTITUTION_ID` เพราะบัญชีฝั่งนี้ไม่ได้อยู่ในวิทยาลัยไหน

**วางไว้คนละโดเมนกับแอปของวิทยาลัย** และควรอยู่หลัง VPN หรือ IP allowlist
ของผู้ให้บริการ — ตัวระบบกันด้วยรหัสผ่าน + การยืนยันสองชั้นอยู่แล้ว
แต่การไม่เปิดหน้าล็อกอินของระบบหลังบ้านให้อินเทอร์เน็ตทั้งใบเห็น
เป็นชั้นที่ได้มาฟรี ๆ

หน้าจอนี้ **ไม่เก็บ token ลงเครื่องเลย** รีเฟรชหน้าแล้วต้องเข้าสู่ระบบใหม่
เป็นการแลกที่ตั้งใจ (ดูคอมเมนต์ใน `lib/platform/platform_api.dart`)

> **ข้อจำกัดของเวอร์ชันเว็บ** — `flutter_secure_storage` บนเว็บถอยไปใช้
> ที่เก็บของเบราว์เซอร์ ซึ่งไม่ได้เข้ารหัสด้วยกุญแจของระบบปฏิบัติการ
> เหมือน Keystore บน Android และ Keychain บน iOS
> เวอร์ชันเว็บจึงเหมาะกับการสาธิตและใช้บนเครื่องของวิทยาลัย
> ส่วนการใช้งานจริงของนักศึกษาควรเป็นแอปมือถือ

ค่าที่ตั้งตอน build ได้

| ตัวแปร | ค่าเริ่มต้น | ใช้ทำอะไร |
|---|---|---|
| `API_BASE_URL` | `http://10.0.2.2:3000/api/v1` | ที่อยู่ API |
| `INSTITUTION_ID` | รหัสวิทยาลัยตัวอย่าง | สร้างแอปแยกให้แต่ละวิทยาลัยได้โดยไม่แก้โค้ด |
| `TERM_ID` | ภาคเรียนตัวอย่าง | ภาคเรียนปัจจุบัน |

## การตัดสินใจออกแบบ

### ออฟไลน์ต้องเห็นข้อมูล ไม่ใช่หน้าจอว่าง

โรงฝึกงานเป็นอาคารคอนกรีตหนาที่มีเครื่องจักรรบกวนสัญญาณ และนักศึกษาฝึกอาชีพ
อยู่ในโรงงานต่างจังหวัด `ApiClient.getCached()` จึงเก็บสำเนาคำตอบล่าสุดไว้
เมื่อต่อไม่ได้จะแสดงข้อมูลเก่าพร้อมแถบบอกว่าเป็นข้อมูลเมื่อไร
ไม่ใช่หน้าจอว่างหรือวงกลมหมุนค้าง

ถ้าออฟไลน์และไม่เคยมีข้อมูลเลย จะแจ้งตรง ๆ พร้อมปุ่มลองใหม่ ไม่เงียบ

### แท็บล่างเป็นตัวอักษรล้วน ไม่มีไอคอน

ผู้ใช้คือนักศึกษาอายุ 15–18 ปีและผู้ปกครองที่อายุมาก ไอคอนที่ประดิษฐ์ขึ้นเอง
มักถูกตีความผิด ส่วนคำไทยสั้น ๆ อ่านได้ทันที และไม่มีเมนูซ่อน
เพราะสิ่งที่ซ่อนคือสิ่งที่หาไม่เจอ

### หัวหน้าจอไม่ใช้แถบสีทึบ

ใช้ป้ายเทาเล็กกับหัวเรื่องดำแทน แถบสีกินพื้นที่บนสุดของจอโดยไม่ให้ข้อมูล
และทำให้ทุกหน้าจอดูเหมือนกันหมดจนแยกไม่ออกว่าอยู่หน้าไหน

### สถานะแยกด้วยรูปทรง ไม่พึ่งสีอย่างเดียว

วงกลมคือปกติ สามเหลี่ยมคือเฝ้าระวัง ข้าวหลามตัดคือวิกฤต
ผู้ชายราว 8% มีภาวะตาบอดสี และหน้าจอบางส่วนถูกถ่ายภาพส่งต่อเป็นขาวดำ

### รองรับตัวอักษรใหญ่ถึงสองเท่า

ผู้ปกครองจำนวนมากตั้งตัวอักษรใหญ่ในระบบ แอปจำกัดเพดานไว้ที่สองเท่า
เพื่อไม่ให้เลย์เอาต์พัง แต่ยังผ่านเกณฑ์การเข้าถึง มีเทสต์ยืนยันเรื่องนี้

### ระยะบรรทัดของภาษาไทย

ตั้ง `height: 1.6` ขึ้นไปทุกสไตล์ เพราะสระบนและวรรณยุกต์ซ้อนกันสองชั้น
ค่าเริ่มต้นของ Material ทำให้วรรณยุกต์ไปชนบรรทัดบน

### วันที่ใช้พุทธศักราชเสมอ

ทุกเอกสารของสถานศึกษาใช้ พ.ศ. การแปลงรวมอยู่ใน `Fmt` ที่เดียว
และมีเทสต์คุมไว้ เพราะเป็นจุดที่ผิดพลาดง่ายและกระจายไปทั้งแอปถ้าเขียนซ้ำ

### ไม่ใช้ไลบรารีจัดการสถานะภายนอก

ใช้ `ChangeNotifier` ที่มากับ Flutter เอง เพราะสถานะของแอปนี้มีไม่กี่ตัว
และการพึ่งไลบรารีน้อยทำให้อัปเกรด Flutter รุ่นถัดไปได้โดยไม่ต้องรอไลบรารีตามมา
ซึ่งสำคัญกับระบบที่ต้องอยู่ไปอีกหลายปี

### เข้าสู่ระบบด้วยรหัสผ่านจริง และผูกกับอุปกรณ์

ล็อกอินด้วยรหัสประจำตัวกับรหัสผ่านที่งานทะเบียนออกให้ และบังคับตั้งรหัสใหม่
ตอนเข้าครั้งแรก เพราะรหัสชุดแรกมีเจ้าหน้าที่รู้ด้วยเสมอ

แอปส่งตัวระบุอุปกรณ์ที่สุ่มเองไปด้วยทุกครั้ง ไม่ใช้ Android ID หรือ IDFV
เพราะเป็นข้อมูลส่วนบุคคลตามแนวทางของทั้งสองแพลตฟอร์ม และบางรุ่นเปลี่ยนค่าเอง
สิ่งที่ระบบต้องรู้คือ "เครื่องเดิมหรือเปล่า" ไม่ใช่ "เครื่องนี้คือเครื่องไหนในโลก"

### ต่ออายุ token เองและรวมคำขอที่ซ้อนกัน

เมื่อ access token หมดอายุ แอปต่ออายุเองแล้วยิงคำขอเดิมซ้ำ ผู้ใช้ไม่รู้สึกอะไร

สำคัญคือคำขอหลายรายการที่เกิดพร้อมกันต้องต่ออายุ **ครั้งเดียว** ไม่ใช่คนละครั้ง
เพราะเซิร์ฟเวอร์หมุน refresh token ทุกครั้ง ถ้ายิงพร้อมกันสามครั้ง สองครั้งหลัง
จะใช้ token ที่ถูกหมุนไปแล้ว ซึ่งเซิร์ฟเวอร์ตีความว่าเป็นการใช้ token ซ้ำ
และเพิกถอนทุก session ทันที ผู้ใช้จะถูกเตะออกทั้งที่ไม่ได้ทำอะไรผิด
มีเทสต์คุมไว้เฉพาะเรื่องนี้

### ออกจากระบบต้องลบแคชด้วย

ไม่ใช่แค่ลืม token เพราะแคชมีผลการเรียนและยอดค้างชำระ ซึ่งคนถัดไปที่หยิบเครื่อง
ไปจะอ่านได้ทันทีถ้าเหลือทิ้งไว้ แอปเก็บรายการคีย์ของแคชไว้เพื่อลบได้ครบ

### ข้อมูลบนเครื่องฝากให้ระบบปฏิบัติการเข้ารหัส

Android ใช้ Keystore และ iOS ใช้ Keychain ไม่เขียนอัลกอริทึมเข้ารหัสเอง
เพราะการจัดการกุญแจเองผิดพลาดง่ายกว่ามาก

ข้อจำกัดที่ต้องรู้ — ปกป้องได้เมื่อเครื่องล็อกอยู่และเมื่อถูกถอดหน่วยความจำไปอ่าน
แต่ไม่ได้ปกป้องจากเครื่องที่ถูก root หรือ jailbreak การตรวจ root และการล็อกแอป
ด้วยไบโอเมตริกเป็นงานคนละชั้นที่ยังต้องทำเพิ่ม

### ไม่สร้าง QR พร้อมเพย์เอง

แอปแสดงเลขอ้างอิง 1 และ 2 ให้คัดลอกไปกรอกในแอปธนาคาร ไม่ได้วาด QR เอง
เพราะรหัสผู้รับชำระ (Biller ID) ออกโดยธนาคาร และ checksum ของ EMVCo
ต้องสร้างฝั่งเซิร์ฟเวอร์ให้ตรงกับที่ธนาคารรับ การเดาเองมีโอกาสได้ QR
ที่สแกนแล้วเงินไปผิดบัญชี ซึ่งแก้ยากกว่ามาก

## สิ่งที่ยังไม่ได้ทำ

- **ผู้ให้บริการยืนยันตัวตนภายนอก** ThaID สำหรับผู้ปกครอง และ Google Workspace
  สำหรับนักศึกษา เพิ่มปุ่มที่หน้าเข้าสู่ระบบและเมธอดใหม่ใน `Session`
  หน้าจออื่นไม่ต้องแก้ เพราะทุกหน้าอ่านข้อมูลจาก `Session` เท่านั้น
- **เช็คอินเข้าออกสถานศึกษาและโหมดฝึกอาชีพ** (A-05, A-06) ต้องใช้กล้อง
  พิกัด และการผูกอุปกรณ์ ซึ่งเป็นงานอีกก้อนหนึ่ง
- **โหมดผู้ปกครอง** (A-07) — สลับดูบุตรหลายคน
- แจ้งเตือนแบบ push และ LINE
- ล็อกแอปด้วยไบโอเมตริก และการตรวจเครื่องที่ถูก root หรือ jailbreak
- คิวส่งข้อมูลย้อนหลังเมื่อกลับมาออนไลน์ (ตอนนี้อ่านออฟไลน์ได้ แต่ยังเขียนไม่ได้)
