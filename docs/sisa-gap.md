# แผนที่ฟังก์ชัน SISA เทียบกับระบบของเรา

สำรวจจากระบบจริงที่วิทยาลัยใช้อยู่ (`ctc.sisacloud.com`) โดยล็อกอินด้วยบัญชี
ของผู้ใช้เอง — **บันทึกเฉพาะโครงสร้างเมนู ชื่อฟิลด์ และรูปแบบเอกสาร**
ไม่มีข้อมูลนักศึกษาจริงในไฟล์นี้ เพราะเป็นข้อมูลผู้เยาว์ที่อยู่ใต้ PDPA
และไม่ได้ช่วยให้สร้างฟังก์ชันได้ดีขึ้น

**ขนาดของระบบนั้น** — 14 หมวด · 176 รายการเมนู · ข้อมูลจริง 2,198 คน
7 สาขาวิชา ทั้ง ปวช. และ ปวส.

สถานะของเรา: **มี** = ใช้งานได้ครบทั้งสามชั้น (DB + API + หน้าจอ) ·
**API** = มี API แต่ยังไม่มีหน้าจอ · **DB** = มีแต่ในฐานข้อมูล ·
**ไม่มี** = ยังไม่ได้ทำเลย · **ไม่ทำ** = ตั้งใจไม่ทำ (ของขายพ่วง)

| ข้อมูลส่วนตัว | คำนำหน้า/ชื่อ/นามสกุล (ไทย+อังกฤษ) · ชื่อเล่น (ไทย+อังกฤษ) · ลักษณะเด่น · หมู่โลหิต · ประวัติการแพ้ยา · โรคประจำตัว · เชื้อชาติ · สัญชาติ · ศาสนา · เพศ · น้ำหนัก · ส่วนสูง · วันเกิด · จำนวนพี่น้อง · สถานภาพบิดามารดา · เป็นบุตรคนที่ · จำนวนพี่น้องที่กำลังศึกษา | มีแค่ คำนำหน้า/ชื่อ/นามสกุล (ไทย) · วันเกิด · เพศ · เลขบัตร (แฮช) |
| ข้อมูลที่อยู่ | ที่อยู่ตามทะเบียนบ้าน · ที่อยู่ปัจจุบัน | **ไม่มีเลย** |
| การติดต่อสื่อสาร | มือถือ · บ้าน · อีเมล · Line ID · Facebook | มีแค่ phone · email |
| ข้อมูลบิดา/มารดา | เลขบัตร/Passport · ชื่อ · นามสกุล · วันเกิด · อายุ · **รายได้** · สถานะ | **ไม่มีเลย** (มีแต่ `student_guardian` ที่ผูกกับ person) |
| ที่อยู่บิดา/มารดา | ตามทะเบียนบ้าน | **ไม่มีเลย** |
| การติดต่อบิดา/มารดา | มือถือ · บ้าน · ที่ทำงาน · อีเมล | **ไม่มีเลย** |
| ข้อมูลผู้ปกครอง | แยกจากบิดามารดา | บางส่วน (`student_guardian`) |
| สถานศึกษาเก่า | ระดับการศึกษาล่าสุด · ปีที่สำเร็จ · **เกรดเฉลี่ยสะสม** · สาขาวิชา · ประเภทวิชา · จังหวัด · ชื่อสถานศึกษา | มีแค่ 3 ช่องใน `application` ตอนสมัคร ไม่ได้ย้ายมาที่ `student` |

**ทำไมเรื่องนี้สำคัญกว่าที่เห็น** — รายได้ผู้ปกครองและสถานภาพบิดามารดาคือ
ข้อมูลที่ใช้พิจารณาทุนและกองทุนกู้ยืม · ที่อยู่ใช้ส่งเอกสารและจดหมายเชิญ
ผู้ปกครอง · ข้อมูลสุขภาพใช้ตอนเกิดเหตุในสถานศึกษา ทั้งสามอย่างเป็นงานจริง
ที่ทำไม่ได้เลยถ้าไม่มีฟิลด์

**และเป็นข้อมูลอ่อนไหวทั้งหมด** — สุขภาพ รายได้ ศาสนา เชื้อชาติ ของผู้เยาว์
อยู่ใต้ PDPA มาตรา 26 (ข้อมูลอ่อนไหว) ที่เข้มกว่าข้อมูลทั่วไป การเพิ่มฟิลด์
พวกนี้ต้องมาพร้อมนโยบายว่าใครเห็นได้ ไม่ใช่เพิ่มคอลัมน์แล้วจบ

## โครงสร้างระเบียนนักศึกษาใน SISA (ดูจากรหัสทดลอง 21293)

ระเบียนหนึ่งคนมี **23 แท็บ**

ข้อมูลส่วนตัว · ตารางเรียน · ทะเบียนวัดผล · การลงทะเบียน ·
ตรวจสอบข้อมูลจบการศึกษา · การรับชำระเงิน · ค่าธรรมเนียม · **การยืมบิล** ·
เรียนเสริม/เรียนปรับเกรด · กองทุนนักศึกษา · พฤติกรรม · ตั้งค่าเวลา ·
**แฟ้มสะสมผลงาน** · ข้อมูลนักศึกษา · **ที่อยู่และผู้ปกครอง** · **สุขภาพ** ·
**การรักษา** · ใบสมัคร · รายงาน · ข้อมูลประชาสัมพันธ์ · **ศิษย์เก่า** ·
**ไฟล์แนบ** · **รูปถ่าย**

### ฟิลด์ในแท็บข้อมูลส่วนตัวที่เราไม่มี

| ฟิลด์ | ทำไมสำคัญ | สถานะหลัง 0053 |
|---|---|---|
| **เลขที่ในห้อง** | ใช้เรียกชื่อและเรียงลำดับในเอกสารของห้อง ต่างจากรหัสนักศึกษา | เพิ่มแล้ว (`student.class_number`) |
| **ความพิการ** 10 ประเภท | ใช้ยันการขอรับเงินอุดหนุนผู้เรียนพิการ — ต้องนับได้ ไม่ใช่ข้อความอิสระ | เพิ่มแล้ว (`disability_kind`) |
| **พาหนะมาเรียน** 9 แบบ | วางแผนรถรับส่ง และประเมินความเสี่ยงการมาสาย | เพิ่มแล้ว (`travel_mode_kind`) |
| สถานที่เกิด | ใช้ในเอกสารราชการบางใบ | เพิ่มแล้ว (`person.birth_place_th`) |
| ความสามารถพิเศษ | ใช้คัดเลือกเข้ากิจกรรม/แข่งขัน | เพิ่มแล้ว (`student.talent_th`) |
| ชื่อเล่น · เชื้อชาติ · สัญชาติ · ศาสนา · ลักษณะเด่น | | เพิ่มแล้ว |
| ครูประจำชั้น | | เพิ่มแล้ว (`student_advisor`) |
| ธนาคาร/เลขบัญชี | ใช้คืนเงินและจ่ายทุน | **ยังไม่มี** |
| กลุ่มหลักสูตรพิเศษ (อินเตอร์ · คอม · กลุ่มการเงิน) | ใช้จัดกลุ่มเฉพาะของวิทยาลัย | **ยังไม่มี** — น่าจะทำเป็น tag ทั่วไป |

### สิ่งที่เห็นแล้วตั้งใจไม่ทำตาม

**หน้าระเบียนนักศึกษาของ SISA แสดงช่อง "รหัสผ่าน" ให้เจ้าหน้าที่เห็น**
(แสดงเป็น `●●●●` พร้อมช่องแก้ไข) — เราตั้งใจไม่ทำแบบนี้ เพราะเป็นสิ่งที่
โปรเจกต์นี้เคยมีแล้วถอดออกไปแล้ว (ข้อ 5 ในรายการที่เคยพังแบบเงียบ ๆ):
ถ้าเจ้าหน้าที่ตั้งรหัสผ่านให้นักศึกษาได้ ก็เข้าระบบแทนกันได้จริง และ
`access_log` จะระบุว่าเป็นฝีมือนักศึกษา — **หลักฐานชี้ผิดคน**

ของเราใช้ `POST /auth/credentials/reset-code` ที่ออก**รหัสรีเซ็ต**ให้แทน
แล้วผู้ใช้ตั้งรหัสผ่านเอง เจ้าหน้าที่ไม่มีวันรู้รหัสผ่าน — ฟังก์ชันเทียบเท่ากัน
แต่หลักฐานยังชี้ถูกคน

## รูปแบบการพิมพ์ใบ รบ. — ตรวจแล้ว

หน้า `Grades/Transcript.php` เป็นหน้าเดียวที่มีสี่งาน แยกด้วยพารามิเตอร์ `tab`
(ต้องไล่ ประเภทวิชา → สาขา → หลักสูตร/รอบเรียน → ระดับชั้น → ห้อง ก่อนถึงรายชื่อ)

| tab | งาน |
|---|---|
| `mass` | จัดการข้อมูลผู้สำเร็จการศึกษา (กรอกทีละหลายคน) |
| `print` | พิมพ์ระเบียนแสดงผลการเรียน |
| `printAs` | พิมพ์ใบรับรองกรณีสำเร็จการศึกษา |
| `number` | กำหนดเลขที่ระเบียนแสดงผลการเรียน / เลขที่ประกาศนียบัตร |

### ระเบียนแสดงผลการเรียน — 16 รูปแบบ

1. ภาษาไทย (สช)
2. ภาษาไทย (สอศ)
3. ภาษาไทย (แนวตั้ง สอศ)
4. ภาษาอังกฤษ (แนวตั้ง สอศ)
5. ภาษาไทย (แนวตั้ง 56)
6. ภาษาไทย (แนวตั้ง 62)
7. ภาษาไทย (แนวตั้ง 62 กระดาษตรา)
8. ภาษาอังกฤษ (แนวตั้ง 62)
9. ภาษาอังกฤษ (แนวตั้ง 62 กระดาษตรา)
10. ภาษาอังกฤษ
11. ปวช. 67
12. ปวช. 67 ภาษาอังกฤษ
13. ปวส. 67
14. ปวส. 67 ภาษาอังกฤษ
15. ปวส. (ต่อเนื่อง) 67
16. ปวส. (ต่อเนื่อง) 67 ภาษาอังกฤษ

**สิบหกรูปแบบนี้ไม่ใช่สิบหกแบบอิสระ** เป็นผลคูณของห้ามิติ —
หน่วยงานที่รับรอง (สช/สอศ) · การวางหน้า (แนวนอน/แนวตั้ง) · ภาษา (ไทย/อังกฤษ) ·
ปีหลักสูตร (56/62/67) · ระดับ (ปวช./ปวส./ปวส.ต่อเนื่อง)
และมิติที่หกที่มองข้ามง่ายที่สุดคือ **กระดาษ** — “กระดาษตรา” คือกระดาษที่พิมพ์
ตราครุฑและหัวเอกสารมาแล้ว เนื้อหาจึงต้องเลื่อนลงและไม่พิมพ์หัวซ้ำ
ถ้าออกแบบเป็นแม่แบบเดียวแล้วสลับ CSS จะพลาดข้อนี้ทันที

รายการเลือกรูปแบบอยู่ในโฟลเดอร์ `folder_report=V-2567` — SISA แยกชุดรายงาน
**ตามปีหลักสูตร** ไม่ใช่มีทั้งหมดปนกัน ปีหลักสูตรที่ต่างกันจึงเห็นรายการต่างกัน

### ใบรับรองกรณีสำเร็จการศึกษา — 5 รูปแบบ

1. หนังสือรับรองผลการศึกษา
2. หนังสือรับรองผลการศึกษาและความประพฤติ
3. ใบรับรองตามระเบียบกระทรวงศึกษาธิการ
4. ใบแทนประกาศนียบัตร
5. ใบแทนประกาศนียบัตร (ภาษาอังกฤษ)

ของเรามี `certification` ใบเดียว — ข้อ 4/5 (**ใบแทน**ประกาศนียบัตร) เป็นคนละใบ
กับใบประกาศนียบัตรจริง ออกเมื่อฉบับจริงหาย ต้องระบุว่าเป็นใบแทน

### เลขที่เอกสาร — ของเราแคบกว่า

SISA เก็บสี่ช่อง — `mass_transcript_prefix` + `mass_transcript_no` (ฉบับไทย) ·
`eng_mass_transcript_prefix` + `eng_mass_transcript_no` (**ฉบับอังกฤษใช้เลขคนละสาย**) ·
`mass_certificate_no` · `mass_certificate_code`

**ปิดแล้วใน 0057** — เพิ่ม `student_graduation.transcript_no_en` และ
`document_series.lang` ทำให้ฉบับอังกฤษเดินเลขคนละสายตามที่ SISA ใช้จริง
พร้อมผลมาตรฐานวิชาชีพผ่าน/ไม่ผ่าน + วันที่ (เดิมมีแต่เลขที่ ซึ่งตอบไม่ได้ว่า
ยังไม่ได้สอบหรือสอบแล้วไม่ผ่าน) และ `institution_document_text` สำหรับ
เกณฑ์การสำเร็จการศึกษาห้าบรรทัดสองภาษา · **เหลือแค่แม่แบบการวางหน้า**
ซึ่งเป็นโค้ดที่แก้เมื่อไรก็ได้ ต่างจาก payload ที่ออกไปแล้วแก้ไม่ได้

### ฟิลด์ที่ใบ รบ. ต้องใช้แต่ payload ของเราไม่มี

จากแท็บ `mass` (กรอกเป็นกลุ่มได้ทุกช่อง)

| ช่องใน SISA | ของเรา |
|---|---|
| วันที่รับเข้าศึกษา | มี (`student.admitted_on`) |
| วันที่ออกจากสถานศึกษา | **ไม่มี** |
| วันที่สำเร็จการศึกษา | มี (`student_graduation.completed_on`) |
| วันที่อนุมัติ | มี (`graduation_approval.approved_on`) |
| สาเหตุที่ออก — ลาออก · จำหน่าย · ลาพักการเรียน · สำเร็จการศึกษาตามหลักสูตร · ศึกษาต่อที่อื่น | บางส่วน — `student.status` ไม่มี “จำหน่าย” และ “ศึกษาต่อที่อื่น” |
| หมายเหตุ (ไทย + **อังกฤษ**) | มี `note` ภาษาเดียว |
| มาตรฐานวิชาชีพ ผ่าน/ไม่ผ่าน + วันที่ | มีแต่ `professional_standard_no` ไม่มีผลและวันที่ |
| เกณฑ์การสำเร็จการศึกษา 5 บรรทัด (ไทย + **อังกฤษ**) | **ไม่มี** — เป็นข้อความท้ายใบที่ตั้งได้ต่อสถานศึกษา |

**แกนที่ใหญ่ที่สุดคือสองภาษา** ทุกช่องข้อความของ SISA มีคู่ไทย/อังกฤษ
ส่วน `issue_document()` ของเราเก็บภาษาไทยอย่างเดียว การเติมทีหลังแพงกว่า
เพราะ `issued_document.payload` **แก้ไม่ได้** ใบที่ออกไปแล้วจะไม่มีวันมีข้อความ
ภาษาอังกฤษ ต้องออกใบใหม่ทั้งหมด

### คอลัมน์ในตารางรายชื่อที่บอกกระบวนการ

`รหัส · ชื่อ · ผลการเรียน · รายละเอียด · มาตรฐานวิชาชีพ ·
ภาคเรียนที่สำเร็จการศึกษา · สาเหตุที่ออก · การเงิน · ทรานสคริปต์ดิจิทัล ·
ตรวจสอบข้อมูลโดยนักศึกษา · หมายเหตุ`

สามคอลัมน์ท้ายเป็นขั้นตอนที่เราไม่มีเลย
- **การเงิน** — เคลียร์หนี้ก่อนออกใบ (ของเรามี `v_ar_aging` แต่ไม่ได้ผูกกับการออกเอกสาร)
- **ทรานสคริปต์ดิจิทัล** — ฉบับอิเล็กทรอนิกส์ที่ตรวจสอบได้
- **ตรวจสอบข้อมูลโดยนักศึกษา** — ให้เจ้าตัวยืนยันชื่อ/นามสกุล/วันเกิดก่อนพิมพ์
  ซึ่งเป็นขั้นที่ทำให้ใบที่ออกแล้ว (และแก้ไม่ได้) ไม่ต้องออกใหม่เพราะสะกดผิด
